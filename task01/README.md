## Ч.2. Python, n=256
Медиана **1.126 с**, 0.03 GFLOPS. Оценка для 1024 - 72 с.

## Ответы
1. **Самый быстрый.** n=128 - ikj, n=512 - ikj. Рейтинг почти не меняется: {ikj, kij} > ijk > jik > kji > jki. На 256 kij чуть обогнал ikj - это шум.
2. **Почему ikj/kij быстрее.** Внутренний цикл идёт по `j`: `b[k][j]` и `c[i][j]` идут подряд по строке. Кэш-линия используется целиком и цикл векторизуется. В ijk/jik внутренний цикл идёт по `k` и `b[k][j]` шагает на строку (MAXN*8 = 6 КБ), так что каждый доступ это новая линия. В jki/kji по `i` шагают и `a`, и `c`, поэтому это худший вариант.
3. **Наклон.** 3.1–3.4 ~= O(n^3). Чуть больше 3 потому что n=128 (3\*128 КБ) влезает в L2, а n=512 (3\*2 МБ = 6 МБ) уже нет. На большом n каждая операция дороже. Разрыв между порядками примерно постоянный (~10–13x jki vs ikj).
4. **Python vs C.** 1.126 с против 0.0051 с (ikj) - ~**220×**. Причины. Интерпретатор, каждый float - объект, списки списков (указатели), нет векторизации. Разница порядков в Python почти не видна: она тонет в оверхеде.
5. **control.** Это c[7][7]: сумма по k для него идёт в одном порядке во всех вариантах, поэтому значение совпадает бит в бит. Ловит перепутанные индексы и незаписанный результат.
6. **Штрассен на малых.** 7 умножений блоков вместо 8 O(n^2.81). Но на каждом уровне 18 сложений блоков, malloc буферов и копирования, поэтому на маленьких n эти накладные расходы съедают выигрыш. Отсюда порог `THRESH`.
7. **Где Штрассен обогнал naive.** На n=128 (0.0015 против 0.0020 с). На 1024: 0.48 против 3.13 с, ~6.5x. Но часть выигрыша - базовый случай ikj (кэш-дружный), а naive - ijk. maxdiff ≤ 6.4e-12 < 1e-6.

   | n | naive | strassen | maxdiff |
   |---|---|---|---|
   | 128 | 0.0020 | 0.0015 | 7.8e-14 |
   | 256 | 0.0210 | 0.0115 | 3.0e-13 |
   | 512 | 0.2450 | 0.0703 | 1.2e-12 |
   | 1024 | 3.1314 | 0.4786 | 6.4e-12 |

8. **GFLOPS лучшего.** ikj: 6.39 (`-O2`), 10.7 (`-O3 -march=native`) - это 15–25% от пика ~43. Упираемся в память, нет блочности, один поток.

## Godbolt (x86-64 gcc 16.2, `-O2 -masm=intel`)
`ijk`: внутренний цикл по k. `a` идёт +8 подряд, `b` +6144 (строка):
```
.L4:  movsd    xmm0, [rdx]          ; a[i][k]
      add      rax, 6144            ; b: следующая строка
      add      rdx, 8               ; a: следующий элемент
      unpcklpd xmm0, xmm0
      mulpd    xmm0, [rax-6144]     ; b[k][j], b[k][j+1]
      addpd    xmm1, xmm0           ; c в регистре
      cmp rax, rcx / jne .L4
```
`ikj`: внутренний цикл по j. `b` и `c` идут +16 подряд, по 2 double (SSE):
```
.L29: movapd xmm0, [rcx+rax]        ; b[k][j..j+1]
      mulpd  xmm0, xmm1             ; * a[i][k]
      addpd  xmm0, [rdx+rax]        ; + c[i][j..j+1]
      movaps [rdx+rax], xmm0
      add    rax, 16
      cmp rsi, rax / jne .L29
```
