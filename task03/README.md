# Задание 3 — чтение ассемблера

`./run.sh` → `asm/*.s`. gcc 15.2 x86-64 + riscv64-linux-gnu-gcc 15.2.
`matmul.c`, `strassen.c` — из task01, `isa.c` — max2/max3/sum/f.

## Находки
- **RV64gc на `-O2` сразу `fmadd.d`**, x86 на `-O2` — нет FMA (нет в базовом x86-64). Зато x86 векторизует SSE2, а RV без `V` — скаляр.
- **6144 в RISC-V = `li 8192` + `addi -2048`**: immediate только 12 бит (−2048..2047).
- **`-march=native` для RISC-V не работает** (кросс-компилятор: `ISA string must begin with rv32 or rv64`), поэтому `-O3 -march=rv64gcv`. В задании походу неточность, но это не точно.
- **RVV `vlse64.v`** — strided load: шаг строки `b` в ijk одной инструкцией (`matmul-rv-O3v.s`). `vsetvli` — длина вектора не зашита.
- x86 `-O3 -march=native`: `vfmadd231pd ymm`, **zmm (AVX-512) не использует**.
- Внутренний цикл ijk/ikj: x86 8/7 инструкций, RV 6/7. `b`: ijk `+6144`, ikj `+8`/`+16`.
- **`max3`**: x86 два `cmov`, без переходов (6). RV — два `bge` (8). С `zbb` — две `max` (3).
- `sext.w` в RV после каждого `int` — 32-битное в 64-битном регистре.
- **`sum`**: x86 `add rax, [rdi]` — load+add одной; RV `ld` + `add`. Индекс `i` → указатель до конца массива.
- **`f`**: формулу n(n−1)(2n−1)/6 gcc не нашёл, честный цикл. Цикл x86 6 инструкций, RV 4: лишние `mov` (2-операндный `imul`) и `cmp` (в RV `bne` сам сравнивает).
- **`f` на `-O2` без пролога** — листовая. Пролог только на `-O0`: RV `addi sp,-48` + `sd ra` (даже без вызовов); x86 `push rbp`, **без `sub rsp`** — red zone 128 Б.
- **Штрассен `rec`**: 7× `call rec`, `addsub`/`base` заинлайнены (видны с `-fno-inline`). База — `cmp edi, 64` / `ble …,64`.
- **x86 `rec`**: 6 `push` + `sub rsp,280` (+8 ret = 336, кратно 16). **7-й аргумент на стеке** (`336[rsp]`) — у x86 6 регистров, у RV 8 (`a0–a7`).
- **RV shrink-wrapping**: часть `sd s*` после проверки порога — база не платит за сохранение.
- Канарейка `fs:40` / `__stack_chk_guard` — из-за массива `M[7]` на стеке.
- **Хвостовой вызов**: `jmp free` / `tail free` вместо `call`+`ret`. `printf` без формата → `puts`, `memcpy` → `__memcpy_chk`.
