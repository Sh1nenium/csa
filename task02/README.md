# Задание 2 - Биты без ветвлений

`./run.sh` - проверки, листинги, замер. gcc 15.2 + riscv64-linux-gnu-gcc 15.2, i5-11400H.

## Итог
- 9 функций в [bits.c](bits.c): `OK` под UBSan, плюс полный перебор 2^32 против `__builtin_*` - 0 расхождений.
- Ни одного перехода в 9 функциях на x86-64, x86-64-v3, rv64gc, rv64gc_zbb. Выбор везде маской, не `?:`.
- UB нет: `sign_extend` маска `~0 >> (64-b)` (сдвиг 0 при b=64, а не на 64), `sat_add32` сумма в `uint32_t`.

## Наблюдения
- **GCC распознаёт идиомы по форме.** SWAR-popcount стал `popcnt`/`cpopw`, таблица де Брёйна стала `tzcnt`/`ctzw`. Двоичный поиск clz и XOR-свёртка parity не распознаны: шаблона нет, а доказывать эквивалентность компилятор не умеет. `__builtin_clz` дал бы `lzcnt`/`clzw`.
- **`and 31` после `tzcnt`.** Компилятор сохранил мою семантику нуля: `tzcnt(0)=32`, таблица даёт 0, `32 & 31 = 0`.
- **`x & (x-1)`** на v3 стало одной инструкцией `blsr`.
- **RISC-V короче x86 в простом коде:** три операнда, нет `mov`-копий. **Длиннее на константах:** `li` + `addi` на каждую 32-битную маску, отсюда 22 в popcount.
- **`bswap32`** на zbb: `rev8` переворачивает все 64 бита, `srai 32` опускает нужную половину.
- **Ветвящиеся версии.** `is_pow2_branchy` GCC в `x & (x-1)` не свернул, цикл с `jne`/`bne` остался. `sat_add32_branchy`: на x86 `jg` + `cmovge`, на RISC-V `bgt` + `blt`.
- **`?:` на RISC-V - ветка** ([demo.c](demo.c)): нет `cmov` в базе.

  | | x86 | rv64gc | zbb | zicond |
  |---|---|---|---|---|
  | `a > b ? a : b` | `cmovge` | `bge` | `max` | `bge` |
  | `c ? a : b` | `cmove` | `beq` | `beq` | `czero` x2 + `add` |
  | `ov ? sat : s` | `cmovs` | `blt` | `blt` | `blt` |
- **`/ 7`** - `imul` на `0x92492493` + `shr 32` + `add x` (магия > 2^31) + `sar 2` + коррекция знака; на RISC-V то же через `mul`. С переменной - `idiv` / `divw`.
- **Обмен трёх через указатели:** tmp 7, XOR 13, арифметика 23 инструкции. Компилятор не упрощает из-за aliasing: `rot3_xor(&a,&a,&c)` даёт `a = 0`.
- **C1:** `x & 0xff` стал `movzx`, `x << 3` стал `lea [rdi*8]`. На RISC-V `x << 3` для `unsigned` дал 3 инструкции (`slli/srai 35` + `slli`) вместо `slliw` - промах GCC.
- **Clang** не ставил; переход в `ctz32` у Clang - из-за `bsf`, у которого результат для 0 не определён (не проверено).

- **Ускорения 1.00 нет, потому что** `-O2` в GCC 16 векторизует SWAR через SSE2, а v3 - скалярный `popcnt`. Без векторизации `popcnt` быстрее в 2.2x.
- **Потолок ~0.57 нс** (~7 ГБ/с), задаёт память - массив больше L3 (не проверял).
